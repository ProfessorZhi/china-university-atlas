# V5.4 · 仅城市级 campus 记录的全量清缴

V5.4 的目标不是把 728 条降成 0，而是让每一条都经过研究并留下可复核的结论。**可以留下无法安全解决的记录，不可以留下没有研究过的记录。**

## 本轮范围

V5.3 结束时，main 上仍有 **553 条** campus 记录只到城市层级。V5.4 把全部 553 条一次性穷尽，不分批试跑。

## 方法

每条记录走三层角色，任一环不过则不落库：

1. **researcher**：按 省 → 市 → 地址类型 → 未解决原因 分片，逐个重找权威来源（学校官网其它页面、招生章程 PDF、信息公开、招标采购、政府转载、教育厅/教育局）。
2. **独立 verifier**：重新抓取原文，不读 researcher 的结论摘要。地址必须与**本条 campus 的地址**挂钩，同校其它校区不作为依据。
3. **仲裁**：仅在 researcher 与 verifier 冲突时启动（本轮触发 0 次）。冲突不投票。

落库前再过硬门禁：`d` 必须出现在引文里；引文必须能挂到本条地址（门牌+路名优先，允许半/全角与省市前缀省略，不允许 `长江路` vs `长江东路`、`100号` vs `108号`）；`d` 必须是 `data/regions.json` 里的法定县级行政区。

**功能区不是法定区**：高新区/经开区/新区/开发区/大学城/产业园/示范区 一律不填入 `d`；但 `沈北新区`、`浦东新区`、`清新区`、`滨海新区` 这类**本身即法定行政区**的不在此列，判据是 `regions.json` 成员资格而非字面包含。

裁决链路：researcher `accept 166 / needs_review 280 / reject 107` → 独立 verifier `accept 118 / downgrade_to_review 48` → 机器门禁再丢弃 3 条（引文未与地址挂钩，或引文不含区名）。落库 115 条的来源等级：学校官网 70、政府/教育系统官方 45；地址挂钩方式：门牌 96、路名 18、整址 1。**本轮没有一条 `corroborated` 被冒充成 `verified`。**

C 类占最大头，且**多是真实存在的功能区地址**（例如记录地址本身写的就是「某高新区某路若干号」）。把 `高新区` 按常识或地图映射到某个法定区，正是本轮明确禁止的动作；没有桥梁证据就保持未解决。

逐条明细（含每条尝试过的来源与最后复核日期）见 [`docs/v5.4-district-audit.csv`](v5.4-district-audit.csv)，553 行，字段：`campus_id, uid, school, campus, address, province, city, status, failure_reason, failure_reason_detail, attempted_sources, last_reviewed`。
