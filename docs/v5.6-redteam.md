# V5.6 · 独立复核记录

本文记录 V5.6「最佳高校」判定的**独立复核**：谁用什么口径复核了什么、发现了什么、
处置结果是什么，以及哪些结论因为输入漂移而**作废**。

## 复核规则

复核者必须满足三条，否则结论不成立：

1. **不读被审实现**。禁止读取 `src/winner-core.js`、`src/city-layer.js`、`src/facts-layer.js`、
   `src/status-layer.js`、`scripts/generate_best_university_coverage.mjs`、`scripts/facts_v53.py`。
   只读发布方原始事实（`data/rankings-shanghairanking-2026.jsonl`、`data/universities.jsonl`、
   `data/campuses.jsonl`、`data/district-associations.jsonl`、`data/sources/moe.csv`）与报告本身。
2. **从零重判**，不是检查实现是否符合描述。复核者先自己算出「我认为谁是赢家」，
   再与报告公布的行对照。
3. **评审期间输入冻结**。报告只要在复核运行中被改写，该轮结论一律作废重做。

第 3 条是本轮付出代价才确立的：有一次复核在 `reports/best-university-coverage.csv`
被重新生成的过程中运行，其部分结论混杂了修复前与修复后的状态，**整轮结论作废**。

## 已收到并已处置的发现

以下是**针对修复前报告**的复核所提出的问题，逐条给出处置。它们不计入对冻结产物的验收结论，
但记录了缺陷是怎么被发现的。

### 1. 66 条 `comparable_ranking` 的 `decision_detail` 是假比较（严重）

复核指出：300 条 `comparable_ranking` 行里，**66 条的 runner-up 根本不在同一把尺上**——
其中 57 条的 runner-up 完全没有名次，9 条属于另一个软科榜系。文案却写着
「在同榜可比名次上优于」。例：漳州、四平、石嘴山、阿拉尔、东莞、常州。

**根因**：`decideCore` 在「恰好一个组能判出冠军」时直接给强证据赢家，没有检查
**该组是否只有一个候选**。只有一个候选的组不存在比较，赢家却借一个不在场上的对手
宣称了一场名次胜利。

**处置**：新增 `soloScale` 保护与 `single_ranked_candidate` 依据（政策，非排名证据），
并给出诚实的文案。复核后的验证：`comparable_ranking` 行中 `runner_up_same_scale=no` 的为 **0 条**，
文案在跨尺时仍声称同尺度获胜的为 **0 条**（见下「本轮验证命令」）。

### 2. 全部 1,220 条区县行的 `location_basis` 为空（严重）

复核指出区县行的 `location_basis` 字段**全为空**。

**根因**：`addRow` 在调用 `decideWinner` **之前**执行了 `entries.map(unwrap)`，
于是 `winner.entry` 变成普通学校对象，丢失了 `hasCampus` / `hasAssociation` / `entityExact`，
`locationBasis` 返回空串、`locationEvidence` 返回 `'entity'`。

**处置**：保留包装对象，先解包再排序；同时把证据档位拆分
（`verified_campus` / `official_unverified_campus` / `corroborated_campus` /
`profile_campus` / `historical_campus` / `other_campus`），并新增结构性守卫：
**任何已解决赢家缺 `location_evidence` 即让生成失败**。

相关的一个附带发现：某区县（北京市密云区，赢家首都经济贸易大学）的赢家依据是
**`historical_campus` 档**的位置记录。旧口径把所有「有校区」压成同一档，
于是「来源已核验的校区」与「来自历史快照的校区」在报告里**看起来完全一样**。
拆档后前者是 `verified_campus`（42 个已解决单元）、后者是 `historical_campus`（137 个），
差异不再被掩盖。

需要注意 `historical_campus` **不等于「已废弃校区」**——它说的是**记录来源**。
同一档里既有北京师范大学（西城区）、合肥工业大学（庐阳区）这类主体校区，
也有确实只由历史快照支撑的位置。

### 3. 北海市被错误地公布为未决（严重）

复核指出北海市的公布理由「领先候选均无官方榜单可比名次，无法判定先后」站不住脚：
广西工业学院（公办）与北海艺术设计学院（民办）同层同级，项目口径下应走公办优先。

**根因**：`decideCore` 里 `if (!ranked.length) return NO_RANKING` 的**提前返回**
跳过了整条政策链。结构完全相同的崇左市、鹤壁市走了公办优先，北海市没有。

**处置**：删除该提前返回，让政策链先跑。北海市现在 `resolved_policy` / `public_before_private`。

### 4. `needs_ranking_backfill` 对全部未决单元失效（中等）

复核指出该标记依赖 `!!winner`，因此 **36 个未决单元一个都没被标上**——
而它们恰恰是最需要补榜单覆盖的。

**处置**：未决单元无条件为 `yes`。KPI 从 325 升到 **492**。

### 5. 未决原因归因错误（中等）

- **沧州市**被标 `cross_system`，而它基于政策的幸存者其实**同榜**，只是共同被 `500+` 区间阻断。
  处置：在被阻断的分支里报告政策幸存者的单尺度原因，现在显示
  「领先候选（沧州师范学院、河北水利电力学院）同榜且均落在开放区间（500+），区间内不排序」。
- **盘锦市**的区间文案对**单个**候选用了「均」。处置：改用 `both` 判断。

### 6. 公办优先递归吞掉了政策标注（中等）

复核发现东莞市等单元的 basis 被内层结果的硬编码 `comparable_ranking` / `strong` 覆盖，
**政策被伪装成了排名证据**。

**处置**：递归结果外层恒为 `basis: 'public_before_private'` / `strength: 'policy'`，
内层结果作为 `innerBasis` 显式披露。

### 7. 判定为「不是缺陷」的两点

- **`prestige_tag` 报 `strong` 不可审计**：985 / 211 / 双一流 是**国家官方认定**
  （教育部名单），不是本项目的自造规则，因此报 `strong` 是公平的。
- **回填标记与某个具体 runner-up 不一致**：`needs_ranking_backfill` 跟踪的是
  **整个判定是否依赖缺失的覆盖数据**，不是某一个 runner-up 有没有名次。
  该语义已写入 `docs/v5.6.md` 第 13 节。

## 本轮自查发现的两个问题（非复核方提出）

1. **我自己引入的回归**：删除 `!ranked.length` 提前返回后，未决单元的 `top` 变成空数组，
   `comparable_candidates` 随之全空。被结构性扫描的 `unresolved_without_candidates` 抓到 **8 条**。
   修复：`const top = champs.length ? champs.flatMap(c => c.top) : items;`
2. **我自己的扫描脚本误报**：8 条 `policy_with_unknown_basis` 是因为临时扫描脚本的
   POLICY 集合漏了新增的 `single_ranked_candidate`。补进集合后归零。
   这类误报不会被当成缺陷，但说明**判定依据集合必须在扫描与实现之间保持一致**。

### 明确拒绝

复核方建议在阶梯中增加一层「跨榜单体系优先」（普通本科压过职业本科）。**拒绝**：
这与 §11 Agent G 直接冲突——它正是规范禁止的自造规则（「职业本科一定低于普通本科」），
发布方从未给出两者之间的换算关系。此类比较一律标 `unresolved_incomparable`。
本项在文档中留档，避免下一轮被重新提出。

### 这一轮的教训

**复核简报必须与发布产物同构。** 第一轮的一则头条结论来自简报自身的 40 条截断，
第二轮的一批结论来自原始行与 `schoolData` 的差异。两次都不是事实分歧，而是
**输入形状**决定的结论。因此复核方拿到的输入必须是构建产物本身，或与之逐字节等价。
