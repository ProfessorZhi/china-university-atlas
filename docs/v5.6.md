V5.5 把「只到城市层级」的 campus 记录逐条穷尽到 284 条 `HARD-BLOCKED`，地点层到此收敛。
V5.6 **不再重搜地点**，转而解决另一个问题：**每一级行政单元的「最好大学」到底是怎么算出来的、
算得对不对、能不能被复核**。

判定过程**：由 `src/winner-core.js` 单点出判定，页面与覆盖审计调用同一个函数，
`tests/best-university-parity.mjs` 断言两者永不背离。

## 4. 字段语义（含容易读错的两个）

`ranking` 与 `rankOverall` 是**发布方自己的两列**，含义随榜单而变，必须按榜单解读：

- **BCUR 11 主榜**：`ranking` == `rankOverall`，都是主榜位次。
- **BCUR 分类榜（21–26 / 745）**：`ranking` = **分类榜名次**，`rankOverall` = **主榜参考**。
- **BCVCR 623 高职总榜**：`ranking` = **类别内位次**（9 个类别各有一个 1），
  `rankOverall` = **总榜位次**。所以 623 的显示 token 必须**带类别限定**，
  否则会把类别名次读成总榜名次。
- **BCVCR 624–632 类别榜**：`ranking` = 类别内位次，`rankOverall` = 全国参考。

发布方对同一行印出两个 token。`_rank_label` 以**当前榜单尺度**的那个为主 token，
另一个作为「主榜参考 / 高职专科总榜 / 全国参考」显式标注；**主榜行（`bcur-main`）
不再加分类前缀**——该行的位次本来就是主榜位次，印上分类名会把它读成分类名次
（改造前会印出「2026软科理工 271 · 主榜参考 271」这种自我重复的假分类名次）。
举例：

| 学校 | 渲染结果 | 含义 |
|---|---|---|
| 北京协和医学院 | `2026软科医药 1 · 主榜参考 14` | 医药类第 1，主榜参考第 14 |
| 河北医科大学 | `2026软科医药 12 · 主榜参考 109` | 医药类第 12，主榜参考第 109 |
| 中山大学 | `2026软科 13` | 主榜第 13 |
| 山西医药学院 | `2026软科医药 56+ · 主榜参考 500+` | 医药类 56+，主榜参考落在 500+ |

## 5. 可比性规则（`comparisonGroup`）

每条事实带 `comparisonGroup` 与 `comparableRank`：

- **同一 `comparisonGroup` 内**的官方名次可以比较。
- **不同榜单体系之间不比较裸名次**：不使用「职业本科一定低于普通本科」这类自造规则，
  也不拿 A 榜的第 5 名去比 B 榜的第 5 名。
- **开放区间不伪精确**：`500+` / `100+` / `80+` / `20+` 是区间，不是数值；
  区间之间不排序，区间与**落在该区间内**的精确名次之间也不排序。
  可行的一对：`480` vs `500+` → `480` 更前（480 < 500）。
  不可行的一对：`520` vs `500+` → 无法判定，标 `unresolved_incomparable_band`。
- **民办榜是独立体系**。公办与民办同层同级时保留 `publicBeforePrivate` 作为**显式的项目政策兜底**，
  报告与 UI 必须显示这是**政策**，不得伪装成排名证据。

## 6. 判定阶梯与状态

`src/winner-core.js` 的阶梯（顺序即优先级）：

1. **层次过滤**：本科 > 专科 > 成人（项目政策）
2. **国家政策标签**：985 > 211 > 双一流（官方认定）
3. **同组冠军**：在每个 `comparisonGroup` 内取冠军
4. **强证据赢家**（`comparable_ranking`）：存在**真正被比较过**的同组冠军——
   恰好一个组能判出冠军、没有任何组不可判，**且该组不止一个候选**。
   最后一条是 `soloScale` 保护：只有一个候选的组没有「比较」可言，
   不能借一个不存在的对手宣称名次胜利。
5. **公办优先兜底**（`public_before_private`，政策）：公办与民办同时在场时，
   对**公办子集递归**调用本阶梯，外层 basis 恒为 `public_before_private`，
   内层结果作为 `innerBasis` 披露（例如「公办优先；公办候选之间再按同榜名次比较」）。
6. **唯一被覆盖候选**（`single_ranked_candidate`，政策）：只剩一个候选被官方榜单覆盖，
   其余候选不在该榜覆盖范围内——按「未覆盖不等于更差」的口径，这不是名次比较。
7. 否则 → `unresolved_incomparable`，**不产生赢家**。

**本轮修掉的阶梯缺陷**：旧实现里有一句 `if (!ranked.length) return NO_RANKING` 的**提前返回**，
它跳过了第 5 步。于是一个「两名候选都无官方名次」的单元（例如北海市：
广西工业学院（公办）对 北海艺术设计学院（民办））会直接落到未决，
而结构完全相同的崇左市、鹤壁市却走了公办优先。删除该提前返回后，同类单元得到同一个答案。
这也修正了第 4 步缺 `soloScale` 时的一类假比较：300 条 `comparable_ranking` 里有 66 条
声称「在同榜可比名次上优于」一个**根本不在该榜上**的候选。

### 三种终态

| status | 含义 |
|---|---|
| `resolved_strong` | 有官方可比名次的强证据赢家 |
| `resolved_policy` | 按**显式政策**决出：单候选 / 本科>专科 / 校区>归属 / 公办优先 / 唯一被覆盖 |
| `unresolved_incomparable` | 领先候选不可比，**不产出赢家** |

### 实际判定依据分布（1,477 个已解决单元）

| decision_basis | 单元数 | 是否排名证据 |
|---|---:|---|
| `single_candidate` | 497 | 政策（唯一候选） |
| `level_order` | 379 | 政策（本科>专科） |
| `prestige_tag` | 203 | 官方认定（985/211/双一流） |
| `public_before_private` | 202 | **政策** |
| `comparable_ranking` | 179 | **排名证据** |
| `single_ranked_candidate` | 17 | **政策** |

只有 `comparable_ranking` 与 `prestige_tag` 报 `strong`；其余四种都报 `policy`，
报告与 UI 都必须这样标注。

### 前置过滤 ≠ 判定规则

第 1、2 步只是**前置过滤**：它们把候选池收敛到「同层同标签」的子集。
当过滤后**只剩一个候选**时，过滤条件本身就是判定规则，`decision_basis` 记 `level_order`
或 `prestige_tag`；当过滤后**还剩多个候选**时，真正的判定规则是子集内的那一步
（同组比较 / 公办优先 / 唯一被覆盖），`decision_basis` 记**那一步**，前置过滤以
`decision_detail` 的第二句披露，例如：

> 宁夏理工学院 是当前候选里唯一被官方榜单覆盖的学校（软科 bcur-private）；
> 候选池先按层次收敛：本科层次优先于更低层次（项目层次政策）

此前 `ctx.basis` 会被无条件回传，于是一个「两名本科候选、只有一所被榜单覆盖」的单元
（石嘴山市）会公布 `level_order`，而**层次规则按定义判不出谁是赢家**——
公布依据无法唯一确定赢家。同类的标签版也会把覆盖规则决出的结果标成
「官方认定」的 `strong`，本轮一并修正：**标签没有把候选项分开时，它就不是判定依据**，
不报 `strong`。

## 7. 旧 `universities.rank` 是历史债务，不是官方名次

迁移前的 `universities.rank` 更接近**旧总榜页面混合展示顺序的 0-based 下标**，
不是发布方公布的名次，**不能包装成标准排名事实**：

- 它**不是赢家**，也**不是排序键**。`mapPriority` 的第三位是显式的**证据档位**
  （官方精确位次 0 < 开放区间 1 < 旧快照 2），旧快照的数字**故意不参与比较**，
  否则会把旧快照排在官方证据之前。
- `rankLabel` 只在**没有任何官方榜单覆盖该学校**时保留，且仅作展示提示；
  这类学校在报告里被标为 `needs_ranking_backfill`。
- 本轮结束后：**legacy 赢家 = 0**，**赢家仍停留在旧快照 = 0**。

## 11. 本轮修掉的两个系统性问题

### 11.1 区间事实被静默丢弃

改造前，`_preferred` 会在遇到 `500+` 这类开放区间行时**丢弃该行**，
让学校掉回旧快照——于是一个**官方已上榜但落在开放区间**的竞争者
在比较里**完全不可见**，另一个有精确名次的学校就拿到了一场它并不配的「干净名次胜利」。

本轮把区间行**保留为 band 事实**（有尺度、无数值），于是它要么作为**阻断性候选**
浮出水面（→ 未决或政策），要么被记为显式的 `public_before_private`。

| 项 | 改造前 | 区间事实修复后 |
|---|---:|---:|
| `resolved_strong` | 554 | **503** |
| `resolved_policy` | 916 | **973** |
| `unresolved_incomparable` | 128 | **122** |
| 赢家仍停留在旧快照 | 134 | **0** |
| 最大未决原因 | — | `cross_system` |

该轮引起的赢家变更 **46 个单元**（全部市级 / 区县级）：
`unresolved_incomparable` → `resolved_policy` 22 个、`resolved_strong` → `unresolved_incomparable`（区间阻断）16 个、
`resolved_strong` → `resolved_policy` 8 个；另有 27 个单元**赢家不变但状态由 strong 降为 policy**，
以及 63 条未决原因文案/归因修正。

`!ranked.length` 提前返回跳过公办优先、以及公办优先递归**吞掉了政策标注**并丢掉 `ctx.basis`。

|---|---:|

| `unresolved_incomparable` → `resolved_policy`（北海市） | 1 |

**17 个**改判 `single_ranked_candidate`（其中 9 个原本被错报为 `level_order`，
见第 6 节「前置过滤 ≠ 判定规则」——层次并没有把候选项分开，它不构成判定依据）。

| 重庆市 · 璧山区 | 重庆机电职业技术大学 | 重庆中医药学院 | 跨榜（民办职业本科 vs 普通本科）裸比名次 |

需补排名单元从 325 升到 **492** 不是退步：新口径把「赢家靠缺失覆盖才成立」的单元
也计入，正是这些单元**最需要**补一轮榜单覆盖。（复核轮修正 `needs_ranking_backfill`
与自身文档语义不一致的问题后，该数落在 **374**：市级 106 / 区县级 267 / 省级 1。）

与它**不同**的一个指标是 `winnerWithoutRankingUnits` = **124**（市级 24 / 区县级 100）：
赢家手上**没有任何已发布名次**（`ranking_scale_field` 与 `ranking_display` 双空），
即用户在地图上看到的是一个没有名次标注的赢家。两者不能互相顶替——
前者问「结论是否依赖尚未获取的覆盖」，后者问「已发布的结论有没有名次可看」。

## 12. 复现性与工作流

- **正常构建不联网**。排名数据只在显式的数据更新流程里抓取；
  CI 与构建使用**已提交的快照**。
- `ci.yml`：build / validate / audit / browser / package，**全离线只读**，不写分支。
- `sync-ranking-facts.yml`：**唯一联网**的工作流，且为手动 `workflow_dispatch`。
  抓取 → 身份校验 → 快照 → 报告 → 重新审计 → 提交 → 推送。
- `release.yml`：仅打 tag 时发 Release，不写分支。
- **没有两个高度重叠的工作流争抢同一个分支**。

构建是确定性的：同一组输入产生同一 HTML；`--check` 守卫在 CI 里断言
`generate_reports.py` / `build.py` / `generate_best_university_coverage.mjs` 的输出未被手工篡改。

排名事实保留 `sourceUrl` 与 `retrievedAt`；身份映射**精确匹配**，未匹配的**不猜**。

## 13. 剩余缺口

374 个单元需要排名补录（省级 1 / 市级 106 / 区县级 267）。成因有两类：
领先候选**不在任何官方榜单上**，或赢家是**因为缺少覆盖才不得不走政策**
（`public_before_private` / `single_ranked_candidate`）。
`reports/best-university-coverage.json` 的 `rankingBackfillPriority`
按受影响单元数排序列出需要优先补录的学校。

`needs_ranking_backfill` 的语义是**该单元的正确性依赖于尚未获取的榜单覆盖**，
不是「赢家没有名次」：一个由 985/211/双一流 或 本科>专科 决出的单元，
补再多榜单也翻不了盘，因而是 `no`；121 个未决单元则无条件为 `yes`。

市 / 区县层的 121 个 `unresolved_incomparable` 单元**不是缺陷**：
它们是本轮刻意保留的「不下结论」，等待更多官方榜单覆盖后再判。
按 blocker 分：`cross_system` 86、`band` 27、`no_ranking` 8。

## 14. 独立复核

本轮由独立的 red team 从零重判：抽样 ≥30 强证据、≥30 政策、≥30 未决单元，
外加一次覆盖全部 3,246 行的**结构性扫描**（含区县校区优先的重新推导）。
复核者**不读被审实现文件**（`winner-core.js`、审计生成器、`facts_v53.py`、各 layer），
只读发布方原始事实与报告本身；任一轮发现系统性问题即**重做全部同类记录**。

复核针对的是**冻结产物**：`reports/best-university-coverage.csv`
（SHA-256 前缀 `6030523445a0a32f`）、`reports/best-university-coverage.json`
（`076a1aa1173a3a61`）、`dist/china-university-atlas.html`（内含 `schoolData`；
把 `VERSION` 提升到 `5.6.0` 只改 manifest 里的版本字符串，`schoolData` 与两份报告**逐字节不变**，
这也反证了覆盖审计确实只依赖 `schoolData`）。
早前几轮复核在报告仍被修改时运行，其结论因输入漂移而作废——**评审只有在输入冻结时才有意义**。

结果与逐条处置见 `docs/v5.6-redteam.md`。

### 14.1 复核发现与处置摘要

第二轮（四路独立复核）共提出 11 类问题。**确认为真并已修复**的是 5 类：

| 编号 | 问题 | 处置 |
|---|---|---|
| B8 / B9 | 报告里的名次标签与地图上印的标签不一致；主榜行被加上了「软科理工 271」这种自我重复的假分类名次 | `ranking_display` 改为发布**与 UI 完全相同**的标签；`_rank_label` 不再给主榜行加分类前缀 |
| E17 | `needs_ranking_backfill` 与自身文档语义不符（把「赢家没有名次」也算进去） | 该标志改为「结论依赖尚未获取的覆盖」；「赢家手上没有名次」拆成独立指标 `winnerWithoutRankingUnits` |
| E17b | 前置过滤（层次/标签）被无条件当作判定依据，即使它**没有把候选项分开** | 公布真正的判定步骤，前置过滤只在其把候选池收敛到唯一候选时才作为依据，否则降级为 `decision_detail` 的第二句披露 |
| B6 | 5 个单元的亚军在**共同尺度**上名次更好，报告没有说明赢家不是靠该比较胜出 | 逐条加显式 note，说明该单元由 `prestige_tag` 决出（这是 §12 声明的国家标签政策，赢家不变） |

**经数据核对后驳回**的是 6 类，驳回理由均落到具体字段：

- **D15 / D14 / A4-C11**：复核者读的是 `data/campuses.jsonl` / `data/universities.jsonl`
  **原始行**，而不是构建产物 `schoolData`。后者会合并 `campusOverrides` 与
  `entityLocationOverrides`——`长沙健康学院` 有一条 `corroborated` 的浏阳市校区行，
  `新疆昆仑科技学院` 的 `p/c` 是「新疆维吾尔自治区 / 草湖市」且当地有 `official` 校区行。
  审计与 UI 都读 `schoolData`，这正是 §18 要求的一致性口径。
- **C12**：复核者引用的 `本科层次优先于本科` 这个串在当前 CSV 里**不存在**；
  该列在 379 行上只有一个取值。
- **40 项候选池截断**：那是**我方复核简报生成脚本**把候选池截到 40 条造成的
  （`poolTruncated.kept = 40`），不是报告的属性——报告的候选池不截断
  （例如北京市 `candidate_count = 92`）。这是**简报方法的缺陷**，已记录。

**明确拒绝**的一条：复核者建议在阶梯里加一层「跨榜单体系优先」
（让普通本科压过职业本科）。这与 §11 Agent G 直接冲突——它正是规范禁止的自造规则
（「职业本科一定低于普通本科」）。此类比较一律标 `unresolved_incomparable`，
本项**维持拒绝**并在此留档。

教训：**复核简报必须保真**。第一轮的一个头条结论来自简报自身的截断，
说明喂给复核者的输入若不与发布产物同构，复核结论会被输入形状而不是被事实决定。
