# V5.7 · Standalone Offline Edition

V5.7 不改变高校、校区、排名或 Best University 判定语义；本轮目标是把 V5.6 已经完成的数据产品做成更轻、更清楚、更适合直接分发的**单文件离线应用**。

## 目标与红线

继续保证：

- 只有一个 `china-university-atlas.html`；
- 直接通过 `file://` 双击打开；
- 不需要本地服务器、安装程序、账号、API key、CDN 或首次联网；
- 正常浏览 `0 HTTP request`；
- 不删除学校、校区、排名事实、边界或 winner 规则来换体积；
- `src/winner-core.js`、覆盖审计与 UI parity 继续保持同源。

## 为什么 V5.6 有 16.8 MB

V5.6 构建产物为 **16,772,793 bytes**。profiling 后确认，主要体积不是 JS/CSS，也不是已经压缩的行政区边界，而是完整 `schoolData` 被以明文 JSON 写入 HTML：

- `schoolData` 明文：14,705,604 bytes；
- 同一份数据 gzip 后：1,217,659 bytes；
- 行政区 gzip：1,467,501 bytes；
- JavaScript / CSS 只有约百 KB 级。

因此本轮不做“删字段换体积”，而是改变**内嵌编码方式**。

## 无损压缩方案

`schoolData` 与 `geoData` 都在构建阶段：

1. 使用 gzip 压缩；
2. base64 内嵌到 HTML；
3. 浏览器启动时通过原生 `DecompressionStream('gzip')` 解压；
4. JSON 解析完成后，主动清空对应 `<script>` 中的大段 base64 文本，避免 DOM 与运行对象长期同时保留一份压缩 payload。

为保持 Windows / Linux 构建字节级一致，构建器把 gzip header 的 OS byte 规范化为 RFC 1952 允许的 `255 (unknown)`；时间戳固定为 0。

## 体积结果

完成 V5.7 前端壳后，profile 为：

- 单 HTML：**3,701,864 bytes**（约 3.70 MB）；
- `schoolData` 原始 JSON：14,705,604 bytes；
- `schoolData` gzip：1,217,659 bytes；
- `schoolData` base64 内嵌：1,623,548 bytes；
- geometry base64 内嵌：1,956,668 bytes；
- JS：约 96 KB；
- CSS：约 18 KB。

相对 V5.6 的 16,772,793 bytes，单 HTML 缩小约 **77.9%**，同时保持全部运行数据。

`scripts/profile_offline_bundle.py` 把 **5,000,000 bytes** 设为 V5.7 的体积回归上限；超过预算会直接让 CI 失败。

## 前端体验调整

- 页面明确标记 `Standalone Offline Edition · 0 HTTP`；
- 启动阶段增加本地解压 loading，而不是白屏等待；
- 地图控制区改成更清楚的浮动工具组；
- 桌面端强化地图 / 列表信息层级；
- 移动端采用地图优先布局，筛选控件横向滚动；
- 主要触摸目标约 42–44 px；
- 超小屏隐藏非核心 SVG/PNG 快捷按钮，避免挤压地图；
- 增加 ARIA、focus-visible 和 `prefers-reduced-motion`；
- `/` 快捷键可直接聚焦搜索；
- 不支持 `DecompressionStream` 的旧浏览器显示明确离线兼容提示，不会联网回退。

## 兼容性

运行时解压依赖现代浏览器原生 `DecompressionStream`。推荐近期版本 Chrome、Edge、Firefox 或 Safari。仓库与完整 ZIP 仍保留未压缩的源数据与报告，因此压缩只影响单 HTML 的分发和运行时加载方式，不改变数据可审计性。
