## 填色方案

### 最终色板（6 色，等明度等彩度，色相绕海色等距）

```js
const palette=[
  '#cde6fa', // L*90.1 C*13.1 h252
  '#ebdef5', // L*90.1 C*12.8 h312
  '#fddade', // L*90.0 C*13.0 h 11
  '#f4dfcb', // L*90.0 C*13.0 h 72
  '#d9e7d0', // L*90.1 C*13.0 h132
  '#c4eae7', // L*90.0 C*13.1 h192
];
```

**构造规则**：在 LCh 空间固定 `L*=90`、`C*=13`，色相 = 海色相位 `221.9° + 30° + k·60°`（k=0…5）。刻意让**海色落在两个填充色相的正中间，两侧各 30°**——这是 6 色等距能给出的最大海陆色相间隔。

**真实拓扑实测（5501 对相邻）**：同色冲突 **0**；相邻 ΔE00 **min 9.79**（1/2 号）、p5 9.79、中位 **18.5**、max 30.6；L\* 极差 **0.1**、C\* 极差 **0.3**、均值 C\* **13.0**。

### 为什么这不再是彩虹

| 反彩虹判据 | 截图基线 | 本方案 | 效果 |
|---|---|---|---|
| L\* 极差（越小越无"轻重"暗示） | 7.8 | **0.1** | 没有哪一格比别的"重" |
| C\* 极差（越小越无"强调"暗示） | 18.2 | **0.3** | 没有哪一格"跳出来" |
| 均值 C\*（越低越像底图） | 18.6 | **13.0** | 落在"有色但不是彩纸"的区间 |
| 相邻 ΔE00 最差（越大越分得开） | 6.16 | **9.79** | **+59%**，且 p5 从 7.59 升到 9.79 |
| 相邻中位 | 24.1 | 18.5 | 略降，但仍在"一眼可分"区间（ΔE00>10 即可辨） |

**这是本方案相对工作树 8 色的决定性优势**：两者都是低彩度方向，但 8 色把 45° 的色相间隔塞进同样窄的明度带，相邻最差只有 6.48（等距 8 色版）而不是 9.79。**色相数量本身就是分离度的除数**：`360/8=45°`，`360/6=60°`。

**邻接规则**：`regionColors()` 的贪心不变——先按度数降序排、再用 `(i+k)%palette.length` 首适应。但有两条硬约束：

1. **`palette.length` 必须 ≥ 6**。实测 5 色时贪心失败，出现**同色相邻**（真实拓扑里 1 对）。5 色及以下不要试。
2. **不要按级别换色板**。当前 `regionColors()` 每层独立着色（`drawMap` 每次重建 graph），这是对的——省/市/县三层各自着色，父亲的颜色不会遗传给儿子，避免"整块一个色"的块状感。保持现状，不要引入"按省级固定主色"的规则：那会让颜色变成层级暗示。

**如果必须保留 8 色**（例如评审坚持色相丰富度），用同构造的 8 色等距版，实测相邻最差 **6.48**（仍优于现状 6.16，也优于工作树的 5.71）：

```js
// 备选（8 色）：L*90, C*13, 海色居中，45° 等距
['#cbe6f9','#dde1fa','#f1dcf1','#fcdae1','#fcdcd2','#f1e0ca','#dfe5cd','#cde9d9']
```

**一个反面例子值得记下来**：把 8 色整体转开、让离海色最近的一格从 50° 拉到 64°（`gap=64`），相邻最差反而掉到 **5.75**——因为剩下 8 个色相被压进 296°（每个 37°）。**"离海色更远"换不来收益，只会牺牲填充之间的分离度。**

**两条结论**：

1. **L2 用 `var(--accent)=#a82b21`，不要用 `#c62d28`**。新填充是 L\*90 的浅色，`#a82b21`（L\*38.1, C\*61.9, h36）直接给出 5.36–5.37，**三态全过 4.5**，而且全站只有一个红（侧栏校名、按钮、地图校名同色）。`#c62d28`（L\*44.3）在浅填充上只有 4.27，必须退役。顺带把 `MAP_STYLE.label.uni` 从 `#a82b21` 改回 `var(--accent)`（值相同，但不要再单独写死一个红）。
2. **L1 用 `#274b5a`（7.26），不要用工作树的 `#45636f`（4.96–4.98）**。`#45636f` 在浅填充上勉强过线，但它只有 0.5 个 L\* 的余量，且活字重是 500（`LABEL_TYPO.region.weight`）、halo 只有 `min(2,max(1,fs*.11))≈1.3px`——一旦将来把填充调深半档就会掉到线下（在**工作树当前**的深填充上是 3.98）。`#274b5a` 对两代填充都安全（工作树 8 色上 5.80–6.58），无需随填充联动。
3. **建议在 `LABEL_TYPO` 里把 `uni.weight` 从 700 提到 800**（校名是用户真正要找的信息，中文小字 400→700 的笔画增益远大于 700→800 的排版代价）。这条属字体域，与 Agent D 的结论不冲突，交由字体审计合并。

## 背景与画布

### 三层表面（页面 / 画布 / 卡片）

| 层 | 令牌 | 建议值 | L\* | C\* | h | 依据 |
|---|---|---|---|---|---|---|
| 页面底色 | `--surface-3` | **`#eff2f1`** | 95.2 | 1.2 | 174 | 近中性微绿灰；vs `#ffffff` cr 1.127 / ΔE00 3.25 → 白卡片（顶栏、侧栏）明确"浮"在页面上 |
| 地图画布（海） | `--canvas` | **`#c7dade`** | 85.8 | 6.9 | 217 | vs 页面 ΔE00 **8.66**；vs 白卡片 ΔE00 11.58 / cr 1.447 |
| 卡片/侧栏 | `--surface` | `#ffffff` | 100 | 0 | — | 不变；地图卡片边框见下 |
| 地图卡片缝线 | `--canvas-edge` | **`#d7e2e0`** | 89.0 | 4.1 | 184 | vs 画布 ΔE00 4.21 / cr 1.092，vs 页面 5.30 → 一条"缝"，不是"框" |

**海色从 `#dceef3`（L\*92.9）降到 `#c7dade`（L\*85.8）的理由**：不是"换一种蓝"，而是**把水从纸变成材料**。`#dceef3` 的 L\* 92.9 已经进入纸白区间（vs 白 cr 1.195），它读作"一张带蓝调的纸"——这正是任何 GIS 默认底图的观感；而它的 C\* 6.7 与新海色 6.9 几乎相同，说明**问题不在彩度而在明度**。降到 85.8 之后：① 陆地（L\*90）比水**亮**，符合"浅陆地 / 深水"的常规读法；② 画布与页面拉开 ΔE00 8.66，地图卡片不再需要边框来"证明自己存在"；③ 海色与新填充最差 ΔE00 7.03（`#cde6fa` 对 `#c7dade`，两者色相差 30°），海岸线描边在此之上再给 ~2.5:1 的线对比兜底。

**评审建议的 `#f6f8f7`：评估后不采纳为画布（但采纳其意图）。** 实测 `#f6f8f7` L\* 97.4、C\* 0.9、vs `#ffffff` **ΔE00 1.95**、vs 页面 `#eff2f1` ΔE00 1.37。作为画布它有三个具体后果：① **地图卡片会变成页面上的一个"洞"**——除了 1px 缝线（cr 1.055）没有任何表面差异，`overflow:hidden` 的圆角也失去意义；② **水会变成全屏最亮的表面**，比页面、比侧栏都亮，而陆地（L\*90）比水**暗**——"暗的陆地包围亮的海洋"是把水陆关系画反了；③ 校区点/标签 halo 全是白色（`#ffffff`），画布一旦接近白色，**halo 就失去作用**（halo 靠"白比底亮"把文字从色块上抠出来，画布 cr 1.069 时白 halo 只在染色填充上有意义，在地图空白处则完全消失）。它的**正确用途是 UI 表面**——工作树已经把它用作 `--canvas` 与 `.legend` 底（`#f5f8f7c9`），建议把这两个位置换成：画布 `#c7dade`、legend 底 `#ffffffd9` + 1px `--border` 边框（否则图例浮在深画布上只有 cr 1.049，等于隐形）。

**没有重边框怎么让卡片分开**：靠**画布本身是一次色调跃迁**（ΔE00 8.66），缝线只需要"收边"而不需要"画框"：`border:1px solid var(--canvas-edge)`（`#d7e2e0`，ΔE00 4.2 与画布）+ `border-radius:var(--r-lg)`（12px）+ `box-shadow:var(--sh-1)`。**不要**：给 `.mapcard` 加 `outline`、加 2px 边框、或给画布加渐变——三者都会把"地图是一张纸"重新拉回"地图是一个控件"。

**导出必须同步**：`makeSVG()`（`app.js:89`）把海色**硬编码**为 `rect fill='#dceef3'`。改 `--canvas` 而不改这一行，导出的 SVG/PNG 会和屏幕不一致（PNG 走同一路径，`makeSVG`→`Image`→`canvas`）。这一处必须读 `MAP_STYLE.canvas`。同时 `makeSVG` 里的导出标题 `#244451`、页脚 `#698391` 也应改为 `MAP_STYLE.label.region` 与 `--muted`，否则每改一次色板就漏一处。

## 边界层级

### 问题：现在的分档按"行政级别"，不是按"视觉角色"

审计时工作树 `MAP_STYLE.stroke` 是 `province:.95 / city:.8 / district:.68`（`#8ba0aa`/`#9db0b8`/`#adbec5`，后者偏暖偏浅）。**最终落地不是这三档**：实装为 `1.0/0.9/0.8` × `#5f7c88`/`#647f8b`/`#6a8490`，理由见文末《落地记录》——三档原值对填充的对比度实测 2.11/1.74/1.49，都在"细线还能读成一条界线"的门槛之下，而宽度阶梯本身被保留下来，所以黑白打印时层级仍然可分。截图基线是**全部 0.75px `#7895a5`**。两种都缺同一件事：**用户看不出"我现在在哪个单元里面"**——地图上没有任何一条线是"当前视图的外轮廓"。按级别分档还有一个副作用：同一条省界线，在全国视图里是 0.95px，进了这个省看它的市界时它只作为市界的一部分出现（0.8px 甚至 0.68px），**同一个地理对象在不同视图里粗细不同**。

### 建议：三档语义分层

| 档 | 语义 | 颜色 | 宽度 | L\* | 与陆地填充最差 cr | 与海 cr | `vector-effect` |
|---|---|---|---|---|---|---|---|
| **T1** | **当前视图外轮廓**（你所在的省/市/县的轮廓；全国视图下为国土并集轮廓） | `#2f6b7f`（`--accent-2`） | **1.5** | 42.2 | **4.61** | 4.11 | `non-scaling-stroke` ✅ |
| **T2** | **同级 / 下级行政边界**（并列的省、市、县之间的公共边，含海岸线） | `#7895a5` | **0.75**（≤430px 视图 0.6） | 60.1 | 2.44 | 2.19 | `non-scaling-stroke` ✅ |
| **T3** | **内部细节**（岛礁、飞地、争议区几何、未命名 ring） | `#8ba0aa` | **0.5** + `stroke-opacity:.8` | 64.6 | 2.10 | 1.88 | `non-scaling-stroke` ✅（**不变**） |

**着色 / 描边的一致性是刻意的**：T1 用 `--accent-2`——全站"导航/链接/已核验"的次级色，含义就是"你在哪里"，与面包屑、侧栏同色；T1 也是**选中态描边**用的同一个色（见下节），于是"我点进去的那个区域"和"当前视图的范围"在视觉上是同一件事，不需要第二套语义。

**T1 怎么画**：`drawMap` 在画完子级之后，**把父级的 ring 用 T1 重画一遍**（`fill:none; pointer-events:none`，插在 `#shapes` 的最前面，即子级之下）。全国视图下画国土并集轮廓。这是最省的做法：父级几何已经在 `S.stack` 里（`current().f`），不需要并集运算。它同时满足三件事：给整个视图"收边"、给出"我在哪"的锚点、以及让子级描边在视觉上落在"内部分界线"的位置——正是制图惯例（外轮廓 > 内部行政区界 > 内部细节）。

**`vector-effect:non-scaling-stroke` 是否每档都对：是，三档都要保留，且不要按档混用。** 理由：① T2/T3 是"发丝线"，缩放成比例放大后在放大视图里会变成电缆（z=6 时 0.75px→4.5px），必须锁；② T1 是导航 chrome，不是地理信息，屏幕上是 1.5px 就应当永远是 1.5px；③ **如果只有部分档锁、部分档不锁，线宽的相对关系会随缩放变化**——放大时 T1 不变而 T2 变粗，最终 T2 会盖过 T1，层级在用户捏合手势的过程中被反转。这是层级系统最不能出的错。**结论：三档统一 `non-scaling-stroke`，层级只由颜色 + 宽度表达。**

**取舍与边界情况**：T3 的 0.5px 在 1x DPI 上会接近不可见（cr 1.88–2.10 也说明它"刻意不可读"）。这**是设计意图而不是缺陷**：岛礁与飞地是纹理，不是信息；它们只需要在放大后"浮现"，不需要在缩小时"被读到"。若评审认为内部细节必须可查，把 T3 改为 `#8ba0aa` 0.5px，**不要**改成 T2 的 0.75px（那会把内部细节提升成行政边界，违反层级）。**不要**用 `shape-rendering:crispEdges`（会毁掉曲线）；T1 加 `stroke-linejoin:round`。

## 悬停与选中

### 现状问题（实测，不是印象）

- 截图版 `#ffe09b`：L\* 90.3、**C\* 37.7**（建议色板均值 13.0 的 **2.9 倍**）、h88。它在**对比度上并不失败**（vs 填充最小 cr 1.01），它失败在**身份**：悬停时区域丢掉自己的色相与彩度，"我刚才看的是哪一格"这个问题在鼠标移开的瞬间就答不上来了。同时它让**任意一个被悬停的区域成为全图最彩的物体**——这就是一个排名信号，和图例里"同色系仅用于区分相邻行政区，不表示排名或层级"这句话直接矛盾。
- 工作树版 `--map-hover:#e3d7bb`：L\* 86.3、C\* 15.3、h92。比 `#ffe09b` 好得多，但有一个具体缺陷：**vs 海 `#c7dade` 的 cr 只有 1.013**——悬停一个沿海省份时，它靠海的那条边在亮度上与海水**几乎完全相等**，边界只能靠 1.3px 描边撑着。另外 h92 与填充 `#f4dfcb`（h72）/`#d9e7d0`（h132）同色相区，悬停橙系或黄绿系区域时色相变化很小。

### 建议：放弃"换一种填充色"，改用叠加层

**结论先行：用一个独立的非交互叠加层，比继续和行内 `fill` 属性搏斗干净得多。** 现在 `.region:hover{fill:var(--map-hover)!important}` 之所以要 `!important`，是因为每个 region 的 `fill` 是**行内表现属性**（`drawMap` 里 `E('path',{fill:colors[i],…})`），CSS 只能靠 `!important` 压过它。而叠加层的做法根本不需要压：

```
SVG 图层（index.template.html）
<g clip-path="url(#mapClip)">
  <g id="shapes">          ← region 的 fill / stroke 完全不动
  <g id="overlayLayer" pointer-events="none">   ← 新增，紧贴 #shapes 之后
    <path id="hoverTint"/>  <path id="hoverEdge"/>
    <path id="selTint"/>    <path id="selEdge"/>
  </g>
  <g id="labelLayer" class="labels">
</g>
```

- 位置在 `#shapes` **之上**、`#labelLayer` **之下** → 染色不会盖住标签，halo 仍把文字从染色上抠出来。
- 四个 `<path>` 都是 `pointer-events:none` 且 `d` 由 JS 按需赋成被指向/被进入区域的 `path` 字符串（`S.base[i].rings` 已经在内存里，取 `S.base[i].el.getAttribute('d')` 即可，零重算）。
- **`!important` 全部消失**，`.region:hover` 规则随之删除；region 的 fill/stroke 就是它的"静止态正身"，不会被任何状态改写。

**具体 CSS**：

```css
/* 悬停：保留本底色相，只压暗 3.4 个 L* + 明确描边 */
#hoverTint{fill:#274b5a;fill-opacity:.06}           /* 实测：ΔL* −3.3~−3.5，ΔEab 3.3~3.8 */
#hoverEdge{fill:none;stroke:var(--map-hover-stroke);stroke-width:1.25;
           vector-effect:non-scaling-stroke;stroke-linejoin:round}
/* 选中：你点进去的那个区域，更沉、更肯定 */
#selTint{fill:#2f6b7f;fill-opacity:.10}             /* = --accent-2 */
#selEdge{fill:none;stroke:#2f6b7f;stroke-width:1.75;
         vector-effect:non-scaling-stroke;stroke-linejoin:round}
```

**实测（六种填充逐一算，含标签对比度）**：

| 状态 | 合成结果（以最暖的 `#f4dfcb` 为例） | ΔL\* | L1 `#274b5a` | L2 `#a82b21` |
|---|---|---|---|---|
| 静止 | `#f4dfcb` | — | 7.26 ✅ | 5.36 ✅ |
| 悬停（6% `#274b5a`） | `#e8d6c4` | −3.4 | 6.60 ✅ | 4.88 ✅ |
| 选中（10% `#2f6b7f`） | `#e0d3c3` | −4.6 | 6.37 ✅ | 4.71 ✅ |

三种状态的标签对比度**全部 ≥4.5**（悬停/选中的最差值即在最暖色上，见表）。`#2f6b7f` 描边对填充的 cr 是 4.61（对海 4.11）——**比最强行政边界线（T2，2.44）高出近一倍**，所以"选中"是地图上最强的线，且它和 T1（当前视图外轮廓）同色同族，含义一致：都是"你在这里"。

**为什么用 alpha 叠加而不是 `filter:brightness()` 或 `mix-blend-mode:multiply`**：① alpha 叠加只改明度、不动色相（实测六色 ΔL\* −3.3~−3.5、几乎无 hue 位移），身份保留；② 不用 `filter`——每个 region 一个滤镜 = 34 个合成层，平移/缩放时会抖；③ 实测 `multiply` 相对普通 alpha 的差异 <0.05 cr / <0.3 L\*，换不来任何可感知收益却引入 `mix-blend-mode` 的兼容面；④ `fill-opacity:.06` 是**透明度**，`stroke` 仍由 `#hoverEdge` 独立控制，两者不会互相牵连。

**键盘可达**：`.region:focus-visible{stroke:var(--accent-2);stroke-width:1.6!important}` 建议改为把 `#selEdge` 的 `d` 也赋给聚焦区域、并额外加一条 `#focusRing` 虚线（`stroke-dasharray:3 3`），这样"键盘焦点"和"鼠标选中"在视觉上可分——当前两者共用 `--accent-2` 描边，键盘用户无法区分。

**一个细节**：悬停/选中的 `<path>` 赋 `d` 时要设 `fill-rule:evenodd`（与 region 一致），否则带洞的飞地几何（如某些区县带内环）染色会糊成实心。

## 校区点

### 现状判定：过重，且两处方向错误

工作树 `drawCampusPins`（`app.js:124`）：`r:4+Math.min(2,S.z*.18)`、`stroke:'#fff','stroke-width':1.5`、填 `#2f6b7f`（已核验）/ `#8a6535`（待核验）。

1. **绝对尺寸过大**：半径 4–6px + 1.5px 环 ⇒ 视觉直径 **11–15px**。主图最强的线是 T1 1.5px、T2 0.75px——**点的白环（1.5px 纯白）比地图上任何一条行政边界都粗**，而纯白是主图里除了标签 halo 之外不存在的颜色。一行 5 个点并排时，视觉重量压过它们所在的区县色块本身。
2. **半径随缩放增大（方向错了）**：`r` 是**屏幕像素**（`x,y` 里已含 `*S.z+S.x`），所以 `r=4+min(2,S.z*.18)` 意味着放大到 `z=11` 时点变成半径 6px——**放大本来是为了看更多细节，点却跟着长大挤占细节**。正确行为是屏幕尺寸**恒定**：`r = 3.6`（不随 z 变），或按 `S.z` 反向补偿 `r = 3.6/Math.max(1,S.z)`（若以地图单位绘制）。
3. **配色其实是这次改动里做对的一件事**：`#2f6b7f` = `--accent-2`（"已核验"在侧栏 chip 里就是这个色）、`#8a6535` = `--caution`（"待核验"）。**保留，不要动**——它让"点色"和"侧栏状态色"说的是同一件事，且消灭了截图版里两个色板外的颜色（`#147b63` / `#d78930`）。

### 建议

| 项 | 建议 | 依据 |
|---|---|---|
| 半径 | **r = 3.6**（屏幕像素恒定，不随 z 增长） | 视觉直径 3.6×2+1（环）= 8.2px，约为主图最粗线（T1 1.5px）的 5 倍，符合"点比线重、但比色块轻" |
| 环 | **1px `#ffffff`**（现 1.5px） | 环的作用是在任意底色上切出"点不是色块的一部分"，1px 足够；`paint-order:stroke fill` 保证环在填充之下、不会吃掉填充面积 |
| 内部 | 实心圆，无内点、无描边图案 | 一个点一个语义，不要用图形区分（三角/方块）——那会读成"类型"，而这里是"核验状态" |
| 颜色 | `#2f6b7f`（已核验，cr 4.61 vs 填充）/ `#8a6535`（待核验，cr 4.07） | 保持；两色对填充的 cr 都 >4，且对海 4.11 / 3.63，任何底色上可辨 |
| 点击热区 | 额外一个 `r=12`、`fill:transparent; pointer-events:all` 的命中圆 | 3.6px 的点的可点区域只有 8px，触屏上必然误点；12px（24px 直径）是 8px 视觉尺寸与 44px 无障碍标准之间的折中。**命中圆要在视觉圆之下**（先 append），并同样绑 click |
| 重叠 | 命中圆重叠时取最近的一个（pointerdown 时比距离），不要都触发 | 一所高校多校区在同一县区是常态 |
| 层级 | 校区点放在 `#labelLayer` **之后**（点压标签）或之前（标签压点）？ | 建议**先 append 点、后画标签**——当前 `drawCampusPins(g)` 在 `drawLabels` 末尾被调用，点已在顶层：**点会盖住校名**。改为让点走 `#overlayLayer` 之前的独立 `#pinLayer`，标签在其上，halo 会把校名从点上抠出来 |
| 缩放行为 | 只在 `kind==='district'` 出现（现状，保留）；z<0.8 时整体隐藏 | 区县层已是最细层，无 z<1 的实际场景；这条只是防止"适应全国后再进区县"的过渡帧出现一堆小点 |

## 验收方式

> 约束：本轮**不跑构建、不跑测试**。以下是"人可复核 + 脚本可复核"两套，全部只读。

**A. 脚本可复核（无依赖 node 一行，读 `dist/*.html` 的 `#geoData`）**

1. **相邻分离度**：把 `docs/v5.8-cartography.md` 里的 `palette` 与 `regionColors()` 原样搬进离线脚本，对真实几何（363 层 / 5501 对）算 CIEDE2000。**断言：`min ≥ 9.0`（本方案 9.79）、`同色冲突 == 0`。** 这条是硬门禁，也正是工作树版（5.71）过不去的那条。
2. **等权重**：**断言 `L*极差 ≤ 0.5` 且 `C*极差 ≤ 1.0`。** 这条机械地保证了"不表示排名或层级"（`v57-ui.js:26` 图例文字已在声明这一点，现在需要数据也成立）。
3. **标签对比度**：对 6 个填充算 `cr(#274b5a)` 与 `cr(var(--accent)=#a82b21)`。**断言两者 `min ≥ 4.5`**（7.26 / 5.36）。悬停/选中的合成结果也要算（6.60/4.88、6.37/4.71）。
4. **海陆分离**：**断言 `min ΔE00(sea, fill) ≥ 6.5`**（本方案 7.03）。
5. **inset 等角**：读 `drawInset` 的 `w/h/px/py` 常量，**断言 `(py/px) ≤ 1.05`**（等角上界 `1/cos16°=1.040`）。这条能把"纵向拉长"这类错误钉死，不需要看图。

### 偏离，及理由

**1. 边界三档的色值：`#5f7c88`/`#647f8b`/`#6a8490`，不是上文表格里的 `#7895a5`/`#8ba0aa`。**

上文"建议"表给的是 T2 `#7895a5`、T3 `#8ba0aa`；但同一份文档"问题"节列出的工作树旧值是 `#8ba0aa`/`#9db0b8`/`#adbec5`。实测这三者对填充只有 **2.11 / 1.74 / 1.49**，全部低于"一条细线还能被读成界线"的门槛，这也正是本节开头那条抱怨的成因。实装值 **3.44 / 3.28 / 3.06**，同时保留 `1.0/0.9/0.8` 的**宽度阶梯**，所以即使转成黑白打印，层级仍然靠线宽可分，不依赖色差。三档对填充的离差极小（±0.01），即"哪一档"只由线宽和上下文决定，不由色相决定。

**2. inset 底板不取海色，取 `MAP_STYLE.insetWater = #8aa6b1`。**

上文主张 inset 是"海的一部分搬过来，不是第三个表面"。实装偏离了这一点，理由是**礁盘的可读性**：inset 里的陆地是 `insetLand = #eef3f1`，它对深水 `#8aa6b1` 是 **2.29**，对海色 `#a5bdc6` 只有 **1.75**——回到海色会让"inset 里是一片近乎空白"这个原始抱怨原样复现（该抱怨已由普通用户测试独立证实）。代价是底板与主海只差 **1.31**，所以面板完全靠 1px `stroke.province` 边框立住（这仍是"靠边框承担组件身份"的做法，未加渐变、纹理、阴影）。

**3. inset 标题：不是"把标题色改深"，而是加一条浅色标题带。**

`#45636f` 在新 inset 水上实测 **2.50**（换成上文建议的 `#274b5a` 也只有 **3.65**，仍不过 4.5）——两条都不合格，因为上文那个 4.44 是对**旧的海色**算的，底板一变深就整体失效。实装把标题放进框顶一条 `insetLand` 色带，`#274b5a` on `#eef3f1` = **8.36**。这样做同时解决第二件事：低对比标题紧邻缩放按钮时会被读成"按钮的说明文字"（普通用户测试的原始表述），而一条有底色的标题带在视觉上归属于面板。
