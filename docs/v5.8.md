## 地图主导改版（第二轮，2026-09-14）

第一轮的结论是"地图被界面挤成中间一块"。第二轮不再做局部 polish，而是重排版式、重画配色与边界、重写标签的放置优先级。**只改前端视觉与版式，不动任何数据**：高校主体、campus、ranking facts、winner 判定与 parity 语义全部未触碰（`best-university-parity.mjs` 的 `problemCount` 仍为 **0**）。

### 一、版式：地图放大

三处叠加的挤压被拆掉：右侧栏 326 → **292px**（761–1050 带宽下 300 → 262），header 从三行压成一行（80 → **约 53px**），并且把写死的 `height:calc(100dvh - 172px)` 换成 `--shell-h:calc(100dvh - 103px)` —— 后者在把 header 压扁之后**回收了每个桌面视口上白白丢掉的 44px**。`drawMap` 的拟合留白同步从 `top=118,bottom=48` 收到 `top=60,bottom=54,left=22,right=40`（`right=72` 只保留给全国层，那里要放南海 inset）。

### 二、配色与边界

**填色**换成 6 色循环 `#f2e7cb #fcd5eb #b9eff7 #ecc3b3 #b7d3b8 #cccff2`：同一个窄色度带（C\*15–18）、比原来更宽的明度带（L\*82–92，原来压平在 L\*90/C\*13）。选色用 CIEDE2000 在 sRGB 内枚举候选、建两两距离矩阵、最远点插入 + 交换局部搜索，**最大化最小两两距离**——因为 `regionColors` 是贪心的，任意两项都可能相邻，只有全对都远的调色板才是可证安全的。最差一对 **11.3 → 14.9**。第一版试过 C\*20 的一档，渲染出来偏糖果色，已退回。

**边界**做成三级：`#edgeLayer` 画当前层外轮廓（2.3px 可见，`#3c5a68`），内部行政区界次之（`.95/.8/.7`），无名的细分边界最弱（`.55`）。`#edgeLayer` 的取巧之处是画在 `#shapes` **下面**：一条 path 串起所有环、`stroke-width:4.6`，不透明的填色盖住内侧 2.3px 和共享描边的每一段内部线，只剩外圈 2.3px 露出来。

新增门禁 **`minAdjacentDE00`**：594 对相邻行政区里，最接近的一对颜色距离 **14.6**（门槛 12），`closeColourPairCount` 与 `adjacentSameFillCount` **都是 0**。

### 三、标签：两级结构 + 引线收成最后手段

上一层的行是「杭州市 / 浙江大学」两级：行政区名用 `#26333b`、小一号、中等字重；最佳高校名用 `#a82b21`、大一号、加粗。行内引线墨色从 `#4a6b78` 压到 `#3d5c68`，因为填色变浅之后对比度一度掉到 3.55:1（门槛 3:1），压深后回到 **4.45:1**。

真正改动的是**放置优先级被写成了控制流**。`place()` 新增 `maxTier` 上限和一条**引线"皮带"**，`drawLabels` 从两趟改成六趟：

```
in place  >  beside it, within the leash  >  name alone  >  anywhere
```

- **皮带（leash）**：一次逃逸最多离自己形状多远，取三者最小——标签自身宽度 ×0.8（宽的组自然属于更大的邻域）、58px 硬顶（再长就不像标注了）、`S.w*0.055`（"旁边"应该是地图的一个比例而不是一个像素数：1440 下是 62px 永不生效，390 下是 20px，正是它挡住了手机上的引线环）。**刻意不含"行政区自身面积"**：用面积做皮带听起来合理（大省能承受更长的引线），但读者能跟住多长的线是**屏幕上那根线**的属性，不是它指向的多边形的属性；用面积反而把皮带收在「§五 明确要保留引线的那些又小又密的区」上，代价是北京图里 `石景山区` 丢了它的胜者。
- **`name alone` 排在 `anywhere` 之前**：这就是 §四 的第 3 条先于第 4 条。上一版里一个只能靠邻省或海面才放得下的单元会**一步拿到引线**，哪怕它自己的行政区名本来能干净地落在自己的形状里——手机上那个 19 个标签的环就是这么来的。
- 最后两趟把皮带整个抬起（`maxTier=Infinity`），所以这条梯子**只决定尝试顺序，永远不决定某个行政区到底有没有标签**：实在没地方就退回家引线，不会凭空消失。这也是这个改动**单调安全**的原因——每一趟只处理前面几趟放不下的单元，一个单元不可能占两个位置。

**引线数量因此从 127（第一轮产物）降到 37**，其中第一轮本轮的版式改版贡献了 127 → 50，这条梯子再贡献 50 → 37。

### 六、没做到完美的

1. **手机全国层仍然引线重：430×932 有 14 条、390×844 有 13 条，区内率只有 0.49。** 原因是物理的而非算法的：430px 宽的地图上，34 个省级单元里东部沿海十几个挤在约 180px 内，而一个两行的「省名 + 校名」组在 9.6px 字号下仍需约 46×25px。§四 允许"少量引线"，14 条算不上"少量"。**本轮把它从 38 条压到 27 条（−29%），但没有解决。** 真正的解法要么是手机全国层不画校名（与 §四"全国层只做每省最佳高校"冲突），要么是换一种手机专属的画面组织方式——两者都超出"重排版式"的范围。
2. **手机全国层 430 缺 2 个、390 缺 5 个单元**（第一轮验收已明确接受"手机全国层隐藏少量标签可以接受"）。
3. **`minLabelFont` 仍是 9.6px**，低于 UI 最小字号 10px（第一轮验收已接受）。
4. **`silentOnAnswer` 从 5 升到 13**（全国 430 6 个、390 5 个、1280 1 个、桌面 0）。这是把"名在区内、校名被拿掉"排在"引线拉出去"之前的**直接代价**，也就是 §四 第 3 条优先于第 4 条的执行结果。桌面端该计数为 **0**，所以 ≥1440 的门禁仍然绿；但它是一条真实的取舍，不是免费的。
5. **`#b9eff7` 这档浅青填色离海色只有约 19.6–20.1 dE00**，是调色板里离背景最近的一项。594 对相邻行政区都过了 12 的门槛，但它挨着海面的那几个省（辽宁、山东、江苏沿海）在低分辨率屏上会略微"贴"在海上。
6. **CI 跑在 Ubuntu 上，没有中文字体**，回退字体的度量不同——`labelsMissing`、`leaderCountRendered`、区内率这些**都会不一样**。上面所有数字都是 Windows 本机读数，不是跨平台常数。门禁是那几条不随字体变的断言（`labelOverlapCount` / `clippedLabelCount` / `labelUiCollisionCount` / `geoOutsideCount` / `wrapGuard` / parity）。

**度量口径（必读）**：上表与全文的 `After` 数值取自 **Windows 10 + 系统中文字体** 的无头 Chrome。CI 跑在 Ubuntu 上，**没有中文字体**，回退字体的度量不同，同一份产物在 CI 上会得到另一组数：`domNodes` **592**（对 603）、`labelsMissing` **8**（对 15）、`labelsPlaced` 256（对 249）。三条硬断言在两端都是 0，其余计数**是环境相关的，不应被当作跨平台常数**。这不是本轮引入的问题——只用系统字体是 §1 的硬约束，度量就必然随系统而变——但它让 CI 第一次跑就挂了，并且挂得有价值，见「Visual decisions」第 7 条。

**断言分两类，不要混用。** 一类读的是**屏幕上渲染出来的东西**（`labelOverlapCount`、`geoOutsideCount`、`wordBreakCount`…），它们依赖字体度量，在 Windows 与 CI 上可以不同；另一类读的是**排版器的判定**（`wrapGuard`），它用合成度量驱动 `wrapText`，与系统装了什么字体无关。**门禁取第二类与那三条几何硬断言**；第一类里凡属环境相关的计数只作为本机留证与交叉印证发布，不作跨平台常数。这一区分是被 CI 逼出来的：`wordBreakCount` 在 Ubuntu 上量的是 `.notdef`，只会变小，拿它当门禁等于让「没装中文字体」冒充「没拆词」。

## Visual decisions

以下每条都是**实测驱动**，不是口味。对比度用同一段脚本对 `src/app.js:15` 的六色填充计算，取最小值。

### 1. 水是一层材料，不是页面底色

`MAP_STYLE.canvas` `#c7dade` → `#a5bdc6`：对六色填充 **1.12 → 1.52**。旧值下海与陆是同一个明度材料，国家读起来像"亮页面上挖的洞"；新值下海是图，陆是底。`--canvas-edge` → `#8aa6b1`。

**代价（已修）**：`MAP_STYLE.island` 是唯一没有跟着海一起移动的值，而它的全部职责就是"与海分离"——`#7f97a3` 对旧海 2.12、对新海只剩 **1.56**，所有未命名陆地要素静默丢掉三分之一的图底关系。已修为 `#5a7480`（对海 **2.52**），并刻意避开两档边界描边色，使岛不会被误读成边界。

### 2. 边界阶梯要能读成界线

三档由 `.95/.8/.65` × `#6f8b96`/`#7895a5`/`#8ba0aa` 改为 `1.0/0.9/0.8` × `#5f7c88`/`#647f8b`/`#6a8490`，对填充 **2.80/2.45/2.11 → 3.44/3.28/3.06**。三档彼此对填充的离差只有 ±0.01，即"哪一档"只由线宽和上下文决定、不由色相决定；宽度仍保留 `1.0/0.9/0.8` 阶梯，所以黑白打印时层级靠线宽可分。`vector-effect: non-scaling-stroke` 保证缩放时粗细稳定。

### 3. 南海诸岛 inset：从"什么都没有的框"到有标题的面板

三处改动，每一处都由实测推着走：

- **底板**用 `insetWater #8aa6b1` 而非海色。审计主张"inset 是海的一部分搬过来"，实装偏离了：礁盘陆地是 `insetLand #eef3f1`，对深水 **2.29**、对海色只有 **1.75**，回到海色会让"inset 里近乎空白"原样复现。代价是底板与主海只差 1.31，面板完全靠 1px 边框立住，未加渐变/纹理/阴影。
- **标题带**。`#45636f` 在新 inset 水上实测 **2.50**，审计建议的 `#274b5a` 也只有 **3.65**——两者都不过小字号的 4.5 门槛，因为那条建议是按**旧海色**算的，底板一变深就整体失效。实装改为在框顶画一条 `insetLand` 色带、标题用 `#274b5a` 压在上面：**8.36:1**。副产物是标题不再被读成"缩放按钮的说明文字"（普通用户测试的原始表述）——有底色的标题带天然归属于面板。
- **字号** 8–9px → **10px**（全宽度统一）。

### 4. 引线必须真的看得见，否则豁免不算数

标签不与自身色块重叠时会被引线连回，`tests/visual-layout.mjs` 据此豁免 mislabel 判定。但原文 **20/34 的标签带引线**，而引线是 `.6px` + `opacity .5`，混合后对填充 **1.73:1**、对海 **1.46:1** —— 等于 `mislabelCount: 0` 是**豁免出来的**，不是量出来的。

改为 `1px` / `opacity 1` / `#4a6b78` / `non-scaling-stroke`（对填充 **4.44:1**），并新增一条不按视口分档的断言：`leaderIllegibleCount`（宽度 <1px、透明度 <0.9、或对比度 <3 即计一次）。同时发布 `leaderMeasured` 与 `leaderWorstContrast`，使这条断言**不能靠"什么都没测到"而通过**——实测 `leaderMeasured: 127`、`leaderWorstContrast: 4.44`，与手算一致。

### 5. 两个文字层级要有明文，而且要在读者会看的地方

地图印两档文字：L1 行政区名（`#45636f`，对填充 4.98）、L2 最佳高校（`#a82b21`，对填充 5.36）。图例里的键行说明了这件事，但它是整屏最小最轻的一行，且排在色板免责声明之后——读者被引去找它，找到的是免责声明，于是把红色读成"警告"。

改法克制：键行用 `order:-1` 排到最前，连接词从 `--muted` 提到 `--ink-2`。不新增元素、不改宽度。之所以用 CSS `order` 而不是挪 DOM，是因为该行插入在 `#zoomInfo` 之后有明确的布局原因（见 `src/v57-ui.js` 注释），那个原因没有变。

### 6. 移动端：折叠次要筛选，把列表带回第一屏

实测 430×932：header 90 + 地图卡 559 + 标题区 80 + **筛选条 157** = 地区列表从 y=912 开始，`itemsVisibleCount: 1`，即**整个列表几乎全在折线以下**。滑动读者看到的是一个色块地图和一条 20px 的缝，无从知道下面还有列表。

根因是我自己引入的：`styles.css` 里那句注释写"两行约 44px"，实测是**四行 157px** —— 一个从未量过的成本数字，差了 113px。

修法：五个"数据范围"类筛选（异地办学 / 成人高校 / 权威依据 / 大学名称 / 标签自动避让）在手机上折进一个纯 CSS disclosure（`#advFilters` + `label[for]` + `display:contents`），**地图标签字号滑块留在外面**——它作用于读者正在看的那张图。桌面端用 `display:contents` 让 wrapper 不生成盒子，五个 label 仍是 `.controls` 的直接 flex 子项，布局逐像素不变。

实测：折叠 59px / 列表可见 **118px**；展开 157px / 可见 20px（与修前完全一致，可逆）。

### 7. 控件与图例不能再抢同一个角

地图卡左下角同时住着图例，右下角是缩放控件列。实测 **390 和 430 都**存在 `legendVsControls` 重叠 **56×25**；390 上还有 `legendVsInset` 重叠 **58×13**。

两者根因不同：

- 控件列：`.mapcontrols{bottom:28px}` 是按**单行图例**定的，图例加上键行后变成 47px 高，于是控件列压在免责声明上。改为 `bottom:62px`，并删掉 ≤430px 那条 28px 覆盖。
- inset：`drawInset` 里读 `legend.getBoundingClientRect().height` 拿到的是 **25px**（首次绘制发生在 `v57-ui.js` 填充图例**之前**，读到的是占位文本高度），而图例最终是 47px，于是为 53px 的占位只预留了 41px。修法是把预留带改成**量出来的最坏值**而非实时读数：47+6+13 = 66（手机）、47+11+14 = 72（桌面），实时测量仍可把它抬高。

修后三处重叠全部为 `null`。

**这一条是 CI 抓出来的，不是本地。** 分支首次推送后 `visual-layout` 在 CI 上挂，报 `insetVsUi: mapcontrols`（1440×900 与 1280×800），而同一份产物在本地是 `pass`。根因:桌面端 inset 与缩放控件同住右下角，把两者分开的只有 `x=S.w-w-72` 里那个**字面量 72**——一个从未被测量过的间距。本地实测：inset 右边界 **1005**、控件左边界 **1009**，**只剩 4px**；CI 的回退字体把控件列撑宽几像素，间距就变成负数。**一个只对一台机器的字体度量成立的间距，不是间距。**

改为测量 `.mapcontrols` 的真实矩形，取 10px 实测间隙；若控件列宽到让 inset 必须移出画布，则改为移到控件上方（两条分支都仍在标题带以下）。用探针把控件列人为撑到 **50 / 92 / 152px** 三档、四个视口共 12 组组合验证：**间距恒为 10px，缩放控件与图例重叠全部为 0**，移动端 inset 位置逐像素未变。

这条也说明测试矩阵里那 14 张截图**不只是留证**：跨平台跑同一份产物，能在本地永远看不见的地方把几何缺陷暴露出来。

**代价（已记录）**：inset 上移后其避让框覆盖了更多地图面积，手机端多隐藏 1–2 个标签（390：7→9，430：4→5）。墨压墨是缺陷，藏标签是 §23/§24 明确允许的取舍、且侧栏保留完整信息，所以这个方向是对的——但它确实有成本，不隐藏。

### 9. 绘制几何必须落在拟合框里（第一轮验收 blocker ②）

**症状**：全国主图的底部有一条被画框硬切的海南/南海轮廓。

**根因**：拟合与绘制用了**两套不同的纬度**。`drawMap` 的拟合循环里有 `if(nation&&(p[1]<18||!f.name))return;`（V5.7 起就存在），但同一个函数的绘制循环把 `f.rings` 的**全部**环原样画出来。于是 fit 排除了 18°N 以南、draw 保留了它——**"fit 不算、draw 又画"的半状态**，一切被画到框外的坐标都由 viewBox 直接切掉。实测被切的只有 `海南省`（133 环 / 848 点，投影后 y 645–913；画框 726），164 个点落在可见的底部条带、558 个点完全在框外。

**改法**：抽出模块常量 `const NATION_MIN_LAT=18`，让拟合与绘制读**同一个数**；绘制侧对每个环算一个 `keepMask`（`!nation || r.some(p=>p[1]>=NATION_MIN_LAT)`），只有 `some` 为真的环进入 path。判据用 `some` 而不是 `every` 是**量出来的**：海南省 133 环中 keepAll 4 / dropAll 129 / **跨越 18°N 的 0 环**——没有任何环被从中间截断，所以"整环保留或整环丢弃"是唯一无歧义的选择，且它**可证明**把所有被画的坐标放进拟合框内（实测主图绘制几何止于框底上方 48px）。

代价：拿掉这些环等于主图不再画 18°N 以南的南海部分——**这不是删数据**，`S.geo` 与边界文件一字未动，且「南海诸岛」inset 本来就承担这段信息的展示职责（inset 早已用 `f.rings.filter(r=>r.some(p=>p[0]>=105&&p[0]<=126&&p[1]<23)&&r.every(p=>p[1]<25))` 做同一件事，本条只是把同一个做法用到主图上）。另外，`labelPoint(f)` 取面积最大的环，海南省的主岛（106 点）仍被保留，所以标签锚点没有移动。

**新增断言 `geoOutsideCount`**（见 `tests/visual-layout.mjs`）：取 `#shapes path` 的**渲染矩形**与画框比较，凡越界即计数，`display:none` 的路径跳过（既然没画，就不可能被切）。取渲染矩形而不是 `getBBox()`，是因为 SVG 的裁剪**不影响** `getBoundingClientRect`——被切掉的部分照样出现在这个矩形里，这正是要测的东西。断言不分视口（越界在任何宽度都被切）。

**对照实验（证明这条断言不是空转）**：把已构建产物里的绘制侧过滤改回 `keepMask.push(f.rings.map(r=>true))`，同一段测量立刻报出 `海南省` 越底边 **187px**、`geoOutsideCount: 1`；用真正构建的产物测得 **0**（14 条路由、264 条被画的 path）。

### 10. 中文校名的断行要按词，不按字（第一轮验收 blocker ①）

**症状**：`浙江工商大学杭州商学院` 会断成 `浙江工商大 / 学杭州商 / 学院`，`大学` 被劈开。

**旧注释是错的，而且它把错误固定了下来。** 上一版 `wrapText` 的文档字符串声称"在排版器能给这个标签的宽度下不存在干净的三分，词边界只有'浙江工商大学'之后和'杭州商'之后"——这个断言的依据是一个**算错的宽度**：它把每行的**目标宽度**（12 字 / 2 行 或 ≈6 字）当成了每行的**上限**。真实上限是 `uniMax` 即 9.2 个全宽字，`浙江工商大学` 恰好 6 字，**放得下**。所以正确的断法是 `浙江工商大学 / 杭州商学院`，旧实现从来没试过它。

**改法**（`src/city-layer.js`）：把"按字贪心填"换成**按词切分 + 动态规划求最平衡切法**。

- `textTokens()` 先把名字切成词：`PROTECTED_WORDS` 里的结构词（`职业技术大学`、`职业技术学院`、`师范大学`、`商学院`、`大学`、`学院`…共 29 条）作为**不可分割的整块**被识别出来，其余按字切；`·`、`-`、`/`、空格作为切点。
- `breakTokens()` 在词序列上做 DP，对每个候选行数 k 求 `Σ(目标宽度 − 行宽)²` 的最小值，目标宽度 `min(maxWidth, 总宽/k × 1.04)`；k 从 1 递增，第一个可行的 k 胜出（行数最少优先）。
  **这里有一个真 bug，记下来**：DP 表不能在 k 之间复用。第一版把 `best[k-1][i]` 连同它**在上一轮 target 下累计的代价**一起带进 k=2，两次 target 混算，于是 7 字的第一行（在 9.2 的目标下更"贵"）看起来比 6 字的（在 5.72 的目标下应该更便宜）更划算，`浙江工商大学杭州商学院` 就出成了 `浙江工商大学杭 / 州商学院`。**每个 k 必须用同一个 target 从头重算整张表**。
- 整块放不下时（例如在 5.4 字预算下的 `职业技术学院`），`wrapText` 返回 `[]`。这正是既有降级路径：`stage()` 里的 `if(withUni&&label.lines.length<=label.nameCount)break;` 会让这个单元退回**只显示地区名**——比劈开 `大学` 好。
- 标点的禁则处理后移：只搬移标点，不可能把已经切好的词重新劈开。

**新增断言 `wrapGuard`**（同一个测试文件）：用**合成度量**驱动 `wrapText`——一个全宽字算 1em、一个半宽字算 0.5em，第 5 个参数注入——因此**与系统装了什么字体无关**。两条不变量：

1. 切出来的行拼回去必须**逐字等于**原名，且每行不超预算；
2. 任何行边界都不许落在 `BOUND_WORDS` 里某个词的内部。

`BOUND_WORDS` 是**测试自己的列表**，刻意**不**从页面的 `PROTECTED_WORDS` 读——导入实现自己的列表的测试，抓不住"这个列表被改短"，而那正是这次故障的成因。

覆盖：10 条 canonical case **钉死具体切法**（含 `浙江工商大学杭州商学院@9.2 → 浙江工商大学/杭州商学院`、`北京师范大学珠海分校 → 北京师范大学/珠海分校`、`电子科技大学中山学院 → 电子科技大学/中山学院`、`中国科学技术大学@7.2 → 中国科学/技术大学`、`内蒙古自治区@5.4 → 内蒙古/自治区`、`职业技术学院@5.4 → 空`），再加一轮**全量语料扫描**：页面上 3 230 个不同的学校名与地区名 × 三个真实预算 = **9 690 组，0 失败**。

`wordBreakCount`（从真实渲染字格里读出来的那个）保留并继续发布——它是唯一来自真实字形的数字——但它**不是门禁**，理由见上面的「断言分两类」。

### 11. 两条维护债顺手还掉

- **`heavyHaloLabels` 是一条恒不触发的死断言。** 它的条件是 `stroke > max(2, fs*.16)`，而 `city-layer.js` 把描边封顶在 `min(2, max(1, fs*.11))`——上限就是 2，条件永假，于是它常年发布 0，**而且就算有人把上限抬成一条肥厚的固定描边它也不会响**。改为对着**上限本身**比：`stroke > min(2, max(1, fs*.11)) + 0.02`，并把上限一并发布。字段更名 `haloOverCapCount`（`heavyHalo` 已经不描述它了）。
- **`MAP_STYLE.canvas` 在 `src/styles.css` 里手工镜像。** 注释写着"两处必须一起动"——注释管不住两个值。测试改为从**样式表里读出作者写的 `--canvas`**（不是 `getComputedStyle`，那会被内联覆写掩盖）与 `MAP_STYLE.canvas` 逐字符比较，不一致即 `canvasVarDrift` 失败。实测 `--canvas: #a5bdc6`，`canvasDrift: null`。这样镜像还在，但**漂移会红**。

### 12. 不改的东西

`winner-core.js` 判定原则、高校主体数据、campus 数据、ranking facts、Best University winner 语义，本轮**一行未动**。`best-university-parity.mjs` 的 `problemCount: 0` 是这件事的证据，不是它的结论。第 9 条丢弃的是**绘制**的环，`S.geo`、边界文件与 `reports/coverage.json` 一字未动。

## CI

`.github/workflows/ci.yml` 顺序：`test_build.py` → `generate_reports.py` → `build.py` → `profile_offline_bundle.py` → `generate_best_university_coverage.mjs` → `validate.py` → `validate_facts.py` → 三条 `--check` → `browser.mjs` → `best-university-parity.mjs` → `visual-layout.mjs` → 上传截图 artifact → `build.py --zip`。

`tests/visual-layout.mjs` 在本轮新增/收紧：

- 新增 `leaderIllegibleCount`（不按视口分档）：引线必须 ≥1px、不透明、对最不利底色 ≥3:1，否则它的标签不再享有 mislabel 豁免。
- 新增 `leaderMeasured` / `leaderWorstContrast`，使上一条不能靠"没测到"而通过。
- **新增 `geoOutsideCount`**（不按视口分档）：`#shapes path` 的渲染矩形越出画框即计数，`display:none` 跳过；`geoPaths` 并排发布，使 0 不可能来自"没测到"。
- **新增 `wrapGuard`**（不按视口分档、**不依赖字体**）：用合成度量驱动 `wrapText`，断言"行拼回等于原名、每行不超预算、行边界不落在 `BOUND_WORDS` 任何词的内部"，10 条 canonical case 钉死具体切法，再对全部 3 230 个名称 × 3 个预算 = 9 690 组做同一组不变量扫描。
- `wordBreakCount` 保留为**本机留证**（从真实渲染字格读出，用于与 `wrapGuard` 交叉印证），但**不再当作门禁**——Ubuntu 上它量的是 `.notdef`。
- **`heavyHaloLabels` → `haloOverCapCount`**：原来的条件（`stroke > max(2, fs*.16)`）对一条封顶在 `min(2, max(1, fs*.11))` 的描边永假，改为对着上限本身比。
- **新增 `canvasVarDrift`**：从样式表读作者写的 `--canvas`，与 `MAP_STYLE.canvas` 比较，把"注释约定"变成机器检查。
- `mislabel` 的 bbox 豁免收紧到 <8px 的单元，且"在 bbox 内但在多边形外"不再直接放行，交给邻居判定。
- 新增 `pinsCoveredCount`：校区点被标签盖住即失去唯一点击目标。

截图与 `reports/visual/v5.8-visual-audit.json` 作为 CI artifact 上传，**仓库只保留桌面全国 1 张 + 移动端 1 张**（§33）；`reports/visual/` 与 `reports/visual-layout.json` 已在 `.gitignore`。

**CI 与本机的差异是这套测试的一等公民，不是噪声。** CI 的 Ubuntu runner 没有中文字体，回退字体让所有文本度量与 Windows 不同，所以：

- CI 上**不要**把 `domNodes` / `labelsMissing` / `wordBreakCount` 这类计数当作回归基线——它们会随 runner 的字体而变。门禁是那几条不随字体变的断言：`labelOverlapCount` / `clippedLabelCount` / `labelUiCollisionCount` / `geoOutsideCount` 必须两端都为 0，`wrapGuard` 因为用合成度量，在两端跑的是**同一个**判定。
- **第一轮验收的第一条要求就是这个**：「不要让 Ubuntu tofu 字体把 `wordBreakCount` 变成 0 就算过。」`wrapGuard` 就是为这句话写的：它不测量字形，只测量排版器的判定，所以在没有中文字体的 runner 上一样有效。
- 反过来，**跨平台跑是有收益的**：`insetVsUi` 这条缺陷在 Windows 上 4px 侥幸成立、永远测不出来，正是 CI 第一次运行就把它抓了出来。凡是不该依赖字体度量代码的地方，现在都改成了实测。

**CI artifact 已检视**（`gh run download` 取回 14 张截图 + 两份 JSON，逐张看过）。CI 截图里**所有中文都渲染成豆腐块**——runner 没装中文字体。这是预期的、**不是产品缺陷**：§1 规定只用系统字体，装了 `Noto Sans CJK` 的 Linux 桌面渲染正常。CI 截图的价值在于**几何**而不是字形：它确认了 inset 与缩放控件已经分开、标题带正常、图例/控件/列表的相对位置正确。**字形质量只能在 Windows 截图上评估**，也就是 `reports/visual/` 那一套。
