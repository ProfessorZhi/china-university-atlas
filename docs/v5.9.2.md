# V5.9.2 · Raster Gesture Cache

V5.9.2 fixes the remaining continuous zoom jank without changing university data, winner semantics, or the offline single-file architecture.

## Root cause

V5.9.1 removed label relayout, per-label transforms, scale-bar recomputation, and glass blur from active gestures, but each animation frame still changed the SVG transforms on `#shapes` and `#edgeLayer`. The JavaScript setter cost was tiny while the browser could still spend real frame time re-rasterizing complex SVG paths and non-scaling strokes.

This is a rendering-path problem, not a consequence of using an offline HTML file. Offline packaging affects load/decompression; the jank happens after load while the browser paints the interactive map.

## V5.9.2 rendering path

At each settled view the app asynchronously prepares a local raster snapshot of the map SVG. It removes the label/measurement layer from that snapshot and renders the remaining map geometry into an in-page Canvas at up to 2× device pixel ratio.

During wheel, trackpad, or drag gestures:

- the real SVG map is not transformed frame-by-frame;
- the pre-rendered Canvas is the visible map;
- only one compositor-friendly `translate3d(...) scale(...)` is changed per animation frame;
- the SVG stays frozen until the gesture settles;
- the scale bar uses only `transform: scaleX(...)` during the gesture;
- labels and glass blur stay suspended as in V5.9.1.

After about 165 ms idle the SVG is committed once to the final transform, labels are laid out once, the raster layer is hidden, and a fresh snapshot is prepared for the next gesture. If a snapshot is not ready, the previous SVG path remains as a safe fallback.

## Measured gate

`tests/premium-atlas-raster.mjs` launches Chrome without `--disable-gpu`, disables background throttling, brings the page to the foreground, and distributes 60 wheel packets across 30 real `requestAnimationFrame` ticks.

The CI gate requires:

- raster snapshot ready before the gesture;
- raster layer active during the gesture;
- SVG `#shapes` transform unchanged during the gesture;
- Canvas transform changing during the gesture;
- SVG visually hidden while the raster is active;
- scale bar updated by compositor transform;
- no SVG fallback frames during the measured gesture;
- exactly one idle label layout afterward;
- final SVG transform committed after settle;
- 95th percentile rAF interval below 45 ms;
- raster-path JavaScript work below 5 ms/frame;
- 0 HTTP requests and 0 runtime errors.

The first green CI measurement on GitHub Actions recorded **p95 16.8 ms**, **max 16.8 ms**, 30 raster frames, zero measured SVG fallback frames during the gesture, and about **0.1 ms maximum JavaScript work** for the raster transform path. Snapshot construction took about **23 ms**, but occurs after settle rather than inside the active gesture.

## Bundle

The standalone HTML remains under the existing 5 MB budget and continues to work via `file://` with no server and no network dependency.
